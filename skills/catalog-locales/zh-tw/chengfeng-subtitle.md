# 字幕

**這是一件事，不是流程的一段。 ** 使用者何時喊它就什麼時候做－剛剪完可以做，
做完又刪了兩句可以再做一次。

它只有一個前提：**帳本已經存在**。不是因為它排在剪輯後面，而是因為沒有帳本，
它不知道哪幾句留著、各自落在成片的第幾秒。

```text
需要   edit-list.json（账本）、transcript.json（逐词稿）
产出   subtitles.json
```

乾完就停，**不指揮使用者下一步**。

先讀取並執行 已配置的成峰工具中附帶的業務階段合同，
判據見 [字幕校對規則](references/subtitle-correction.md)，專名寫法見
當前項目或現有成峰工具附帶的術語詞典。

## 誰說了算什麼

這是這一段的地基，其餘都從這裡推出。

```text
剪口播   说了算「留哪些话、在什么时候」    ← 时间的唯一真相
字幕     说了算「屏幕上显示什么字」        ← 显示的唯一真相
```

一螢幕字幕存的是**字 id 清單 + 顯示文字**，**不存秒數**。時間每次從帳本現算。
於是兩本帳沒有第二份時間可以走偏，失效也能精確到屏：「第 7、第 12 屏的詞被剪掉了」，
而不是那句誰也點不動的「字幕可能已過期」。

**字幕存自己的文字是故意的。 ** 轉錄回答「他說了什麼」，字幕回答「給人看什麼」——
標點、去掉的口頭禪、專名的正式寫法，這些本來就該不一樣。逼一份字串同時乾兩件事，
字幕就永遠加不了逗號。

## 0. 就緒

先執行 本機就緒檢查（僅查看已設定的工具、專案與輸入，不下載安裝更新）－skills 是否
最新、Runtime 是否配套；**插件根**也在那裡定位（本文命令裡的 `<插件根>` 都代入
那個字面路徑）。只有「就緒」才會繼續；「需新會話」或「停」按它的處置執行
（含「禁止自製替代介面」禁令），業務 Skill 不自備環境邏輯。

若就緒結果為 `runtime.kind=desktop-managed`，直接重複使用桌面 App 已安裝的穩定 CLI 與
同一 `launchd/windows-task` 服務；不要解析 Electron 路徑、另裝依賴或起第二個
運行時。

## 1. 入口斷言

```bash
node "<插件根>/scripts/ensure-running.cjs" --json
node "<插件根>/scripts/videocut-cli.cjs" inspect "<项目目录>" --json
```

| 斷言 | 不成立時 |
| --- | --- |
| `edit-list.json` 存在且有片段 | 說清楚缺帳本，讓用戶先喊剪口播。 **不要自己去剪。 ** |
| `transcript.json` 存在 | 項目還沒準備好，停止。不要自己造一份。 |

**不要斷言 `source_cut.mp4`，也不要去轉錄。 ** 字幕兩樣都不需要－見下一節。

## 2. 改字：先辭典，後文稿

**不需要重新轉錄。 ** 原來那份逐詞稿已經帶著時間戳，帳本知道哪幾段留著——
每個字落在成片的第幾秒是**算出來的**，不是再聽一遍聽出來的：

```text
词在源片的第几秒   转录里就有
哪几段留着         账本里就有
词在成片的第几秒   两者一算就出来
```

再送一次 ASR 只是把同樣的話重新聽一次，花錢、花時間，而且聽得更差——專名要重新改一遍。
（`transcript retranscribe` 是上一版設計的遺留，那時字幕打算靠轉寫剪後影片拿時間軸。
字幕改成錨詞 id 之後這個問題就沒了。 **做字幕不要用它。 **）

兩件不同的工具，都要用。

```bash
# 词典：这个说话人的固定写法，不需要证据
node "<插件根>/scripts/videocut-cli.cjs" transcript dictionary "<项目目录>" --dictionary "<插件根>/references/ai-term-dictionary.md" --json

# 文稿：作者手上有稿子时才做，逐处要证据
node "<插件根>/scripts/videocut-cli.cjs" transcript align "<项目目录>" --script "<口播稿文件>" --json
```

```text
词典    永远这么写            不看上下文，直接改，列出改了哪几处
文稿    上下文对得上才这么写   逐处要证据，对不上的报「不敢定」，不猜
```

**為什麼一定要有字典，光靠文稿不行**：口播會重錄。真實項目裡同一句錄了四遍，
於是「連接叉」「叉是」這些上下文全都出現不只一次，align 只能報「不敢定」——
它按規矩不猜，因為**名字寫錯比聽錯更糟**。三處「叉」它只敢改一處。
字典沒有這個問題：在這個說話者的作品裡，「叉」**就是**「X」。

**字典只有一份**，在插件級 `references/ai-term-dictionary.md`：它改的是轉錄，
而剪口播和字幕吃同一份轉錄。不要再在這個 skill 下面再建一份。

**改完要看那份清單。 ** 字典不看上下文，所以它也會改錯－－例如把說話者真的說的
「Skills」（Claude Skills，複數專名）normalize 成「Skill」。看到不對就改字典，
不要在指令這邊打補丁。

`transcript align` 只報不改。要應用它的提案，把 `corrections` 轉成 `[{wordId, text}]` 再跑：

```bash
node "<插件根>/scripts/videocut-cli.cjs" transcript correct "<项目目录>" --file "<修正文件>" --json
```

改完轉錄，**引用了這些字的字幕畫面會在同一步跟著改寫**，回報 `subtitles.updated`。
改不動的（那一行被人重寫過）進 `needsAttention`，報出來讓人看，不猜。

**字典裡沒有、文稿裡也沒有任何一個寫法能確認正確時，不許猜。 ** 報出來讓用戶補字典——
補進字典下一影片就自動對了，猜對一次下次還要再猜。

## 3. 分割畫面

```bash
node "<插件根>/scripts/videocut-cli.cjs" subtitle build "<项目目录>" --json
```

四條規則，依序：

```text
① 这里删掉过话    删掉的两边在时间轴上挨着，意思上毫无关系。
                 删掉的是「静音」不算 —— 把句子中间的停顿剪掉，不能把句子劈开。
② 任何标点        火山给的，句号和逗号都算 —— **和剪口播分段是同一个粒度**，
                 两边断在同一处。标点比任何时间证据都强：说话人可以两句连着
                 说不喘气，也可以在一句中间停顿。
③ 段落边界 + 停顿  **只在这个词没有标点时才用**。它是「没标点时靠段落猜句子结束了」，
                 有标点就该由②和逗号那条管 —— 它们会考虑屏够不够长，③ 不会。
                 （在带标点的边界上也触发③，真实项目从 40 屏变 43 屏，切出更多碎屏）
④ 观众听到长停顿   句子内部要断，得有更长的静音才够格。
```

**剪口播和字幕吃同一份標點，粒度也一樣**：一個逗號一段 / 一屏。

碎片（一兩個字）會被並掉，但**不跨句號並** —— “你看”開啟新的一句，
不是上一句的尾巴，往前並會得到「…叫Grok CLI你看」，兩句糊在一起。

說話者說得快的短句會留下來（真實項目上「每天早上」「執行任務」各 0.6 秒）。
**那是他真的這麼說的，不報警。 ** 一個逗號一屏必然產生這種屏，
為它報警等於對正常說話報警——報多了就沒人看警告了。

剩下比一屏長的，均攤拆成幾屏，**一屏一行**。切出一兩個字的碎片，說明②那個邊界
其實不是句號，把碎片並回上一畫面。

命令回報四件事，都要看：

```text
stale              被剪辑改动的屏 —— 精确到第几屏、丢了哪几个字
tooFast            字太多、时间不够读
transcriptMoved    转录已经不是当初那一份了
```

### 已經有字幕時 —— 這裡要停下來問

不加 `--replace` 它會直接拒絕。 **這是這個 skill 裡唯一要徵求用戶同意的地方**，
因為 `--replace` 沖掉的是人花時間做的分割畫面和措辭，產品自己恢復不了。

```text
用户想改几个字     不要 build。让他在 Studio 里直接改，或者告诉你改哪几屏。
用户要推倒重来     确认过了再加 --replace。
```

## 4. 複核：在 Studio 裡逐屏看

```bash
node "<插件根>/scripts/videocut-cli.cjs" open "<项目目录>" --json
```

打開後切到左邊欄的**「字幕」標籤頁**。一行一屏：左邊序號和時間，右邊就是字，點進去直接改。

- **回車** = 從遊標處另起一屏
- **行首退格** = 併入上一屏
- 右欄「參數 → 字幕」四個預設選一個，全片一個樣式
- 畫面上能直接看到字幕，位置和字號跟畫面成比例——**預覽和成片是同一套數**

複核時至少讓使用者確認：專名對不對、有沒有吞字、斷句讀起來順不順、一屏停留夠不夠讀完。

## 5. 到 `subtitles.json` 為止

**這一段做完了。 ** 不做實體剪下、不做分鏡、不做動畫、不渲染成片，**也不催使用者下一步**。

報告必須分開寫入：Product 結構化 readback 為 **API/readback PASS**；真實同專案瀏覽器幀
審核是 **visual frame PASS**；沒有人實際看過字幕跟畫面對不對時一律為
**human listening UNVERIFIED**，不得以 DOM、截圖或檔案探測替代。

## 邊界：燒進畫面不是這一段的事

產出方式定的是**燒進畫面**，而畫面是導出那一段畫的。字幕的產出就是 `subtitles.json` ——
裡面的尺寸全是畫面的百分比，導出以輸出解析度換算成像素即可，兩邊同一套數。

**今天匯出的 mp4 裡沒有字幕**，那一步還沒做。報告裡要寫清楚這個後果，
不要說「字幕做好了」就完事——用戶會以為成片裡有。

## 恢復與失敗

- `subtitles_exist`：已經有字幕了。 **先問，別直接 `--replace`。 **
- `revision_conflict`：另一處也在寫。重新讀取，不自動覆蓋。
- 字典報「第 N 行讀不懂」：那是一行格式壞掉的表格行。規則只認表格行（`| 正确写法 | 常见误识别 |`），
  散文和清單都會被安靜忽略。
- `transcript correct`報「不得更改任何單字id、時間或間隙標誌」：
  改字的提案裡混進了改時間的東西。改字就只改字。
- `runtime_unhealthy`：不要循環重裝。
- 任何失敗都不得把「轉寫完成」說成「字幕做好了」。 **ASR 出來的是原料，不是產物。 **
