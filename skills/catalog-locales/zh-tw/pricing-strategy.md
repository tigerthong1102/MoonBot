# 定價策略

## 概述

定價是三項決策、一項操作。決策：客戶支付的單位（
價值指標）、每個計劃包含的內容（包裝）以及金額（等級）。操作方式：移動
新客戶和現有客戶都可以在不破壞帳單或信任的情況下獲得結果。大多數定價問題
坐在前兩個決定中；大多數定價項目只涉及第三個。

這項技能始於企業已經擁有的證據（帳單記錄、每個帳戶的使用情況、
銷售說明），在證據薄弱的地方添加研究，並以帶有遷移的定價備忘錄結束
計劃。沒有付費客戶的產品仍會走第 2 步驟中的捷徑。

## 使用說明

### 1. 收集事實

讀取 `.claude/product-marketing-context.md`（如果存在）。了解程式碼中如何定義計劃
（搜尋計劃名稱、限制和價格識別碼）並匯出目前目錄：

```bash
curl -G https://api.stripe.com/v1/prices -u "$STRIPE_SECRET_KEY:" \
  -d active=true -d limit=100 -d "expand[]"=data.product
```

然後在可能的情況下取得每個帳戶：計劃、折扣後實際支付的金額、開始日期、
計費週期、席位、每個候選指標的使用情況、使用的功能以及帳戶是否
攪拌或擴大。詢問用戶哪些數據無法告訴用戶：

1. 目標：每個客戶獲得更多收入、更多客戶、更大的買家或覆蓋使用成本。
2. 已做出的承諾：「終身鎖定價格」、合約條款、訂單中的續約上限。
3. 交易如何完成：自助服務、銷售協助或兩者兼而有之，以及需要折扣的頻率。
4. 買家指定的替代方案，包括不執行任何操作或使用電子表格。

### 2. 還沒有客戶：設定第一個價格

如果沒有什麼可診斷的，請跳過步驟 3 和 8，並保持結構最小化：一個指標、一個或
兩種計劃，按月和按年計費，試用而不是免費計劃，直到知道付費原因為止。

- 把價格括起來。底價：每位客戶的變動成本加上付款費用。天花板：結果如何
  對買方來說是值得的（節省的時間乘以每小時的成本、獲得的收入、更換的工具）。
  參考：他們今天在替代方案上花了多少錢，包括手工完成這項工作。
- 訪談 10 至 15 位目標買家。詢問他們現在使用什麼以及費用是多少，展示產品，
  然後說出價格並觀察反應。 「你願意付什麼錢？」產生低且不可靠的數字。
- 請求承諾（預訂、付費飛行員、存檔卡）；意見不等於購買。
- 從買家不議價就接受的上半部中選擇。價格太低
  不能與需求疲軟區分開來，而且後期折價比加價更容易。
- 以標價的日期折扣（而不是更低的標價）獎勵早期客戶。
- 前 20 至 30 名付費客戶或 90 天後進行審核；記錄反對意見並立即表示同意。

### 3.找到弱點

| 證據 | 可能的問題 | 轉到 |
|---|---|---|
| 5 人帳戶和 500 人帳戶支付相同的費用 | 指標不遵循值 | 步驟 4 |
| 帳單波動和顧客要求上限，或為了省錢而限制使用量 | 指標是不可預測的或懲罰採用 | 第 4 步 |
| 80% 的客戶採用一種計劃，或銷售人員不斷分拆功能以關閉 | 計劃與買家群體不匹配 | 第 5 步 |
| 幾乎沒有價格異議，折扣很少，成交率異常高 | 等級太低 | 第 6 步 |
| 大多數交易都需要折扣；流失原因提到價格 | 對於顯示的價值來說等級過高，或買家錯誤 | 步驟 5 和 6 |
| 免費帳戶保持活躍數月且從不付費 | 免費方案給出了付費原因 | 第 5 步 |

### 4. 選擇價值指標

根據使用數據而不是意見對每個候選人進行評分：

| 測試| 如何檢查|
|---|---|
| 隨著客戶獲得的價值而成長 | 擁有更多價值的帳戶保留並擴展更多 |
| 買家可以預測帳單 | 他們可以在發票前註明下個月的數字 |
| 可計數、可審核 | 產品已記錄並可展示給客戶 |
| 不會阻止使產品黏性的行為 | 協作功能的每席定價會抑制邀請 |
| 將客戶分散開來 | 如果 90% 的帳戶屬於最低範圍，則不會將任何人分開 |
| 當成本重要時遵循成本 | 計算、訊息、AI 調用 |

形式：固定費用、每個座位、計量使用、有使用範圍的計劃、平台費加使用量、每個
結果。當兩個指標得分良好時，就對其中一個指標進行控制，並用另一個指標來制定計劃。對於分層
使用量，在分級等級（每個單位按其所屬範圍定價）和數量等級之間進行選擇
（所有單位按區間定價）；畢業避免了帳單下降到閾值。

### 5. 打包計劃

1. 根據需要命名買家群體，其中兩到四個。公司規模只是一個指標，而不是一個需要。
2. 根據每組的採用情況，加上最佳/最差排名，將每個功能分類到四個箱子之一
   當未發布功能的採用資料遺失時進行調查（MaxDiff）：
   - **每個計劃：**需要達到核心價值。門控它會減少啟動。
   - **計劃差異化因素：** 一組晉升的原因。每個計劃一到三個。
   - **附加功能：**受到跨群體的少數人的高度重視。
   - **針對大買家的控制：**安全審查項目、審核日誌、正常運作時間條款、發票。
3. 給每個計劃一個價值指標的標題限制，因此下一個計劃就是以下問題的答案：
   成長而不是尋找功能。
4. 每個計劃都需要指定買家。一個不適合任何人選擇的計劃是混亂的。
5. 免費方案或試用：免費方案適合帳戶服務成本較低且免費用戶帶來的情況
   其他或內容；當價值在幾天內顯現且服務成本顯著時，限時試用適合
   是真實的。無論哪種方式，付費原因都必須排除在免費津貼之外。

### 6. 設定級別

證據，最有力的第一：真實買家接受或拒絕的價格（贏利說明、折扣
歷史記錄，對新註冊用戶的即時測試），然後是調查，然後是競爭對手的價目表，其中顯示了
買家的參考點，與你的價值無關。

調查方法：

- **價格敏感度計（Van Westendorp）：** 每位受訪者有四個開放性問題：價格為
  該產品太便宜而無法信任，討價還價，變得昂貴，並且太貴而無法信任
  考慮。產量在可接受的範圍內。
- **Gabor-Granger：** 價格階梯的購買意願；需求乘以價格給出所得曲線。
- **聯合：**捆綁之間的選擇；包裝和價格相互作用時的正確工具，以及
  三者中唯一需要專業軟體的之一。

詢問與目標買家配對並了解產品的人，每個計劃和一個計費週期
問題。將每組少於 100 個可用答案視為定向答案。

```python
"""Usage: python3 psm.py survey.csv
Columns, one row per respondent, same currency and billing period: too_cheap, cheap, expensive, too_expensive"""
import csv, sys

rows = [{k: float(v) for k, v in r.items()} for r in csv.DictReader(open(sys.argv[1]))]
valid = [r for r in rows if r["too_cheap"] <= r["cheap"] <= r["expensive"] <= r["too_expensive"]]
n = len(valid)
grid = sorted({v for r in valid for v in r.values()})

def at_least(col, p): return sum(r[col] >= p for r in valid) / n   # falls as the price rises
def at_most(col, p): return sum(r[col] <= p for r in valid) / n    # rises with the price

def crossing(falling, rising):
    prev = None
    for p in grid:
        gap = at_least(falling, p) - at_most(rising, p)
        if gap <= 0:
            if prev is None or gap == 0: return p
            p0, g0 = prev
            return p0 + (p - p0) * g0 / (g0 - gap)
        prev = (p, gap)

print(f"{n} of {len(rows)} respondents usable (answers in ascending order)")
print(f"lower bound (too cheap x expensive):      {crossing('too_cheap', 'expensive'):.2f}")
print(f"optimal (too cheap x too expensive):      {crossing('too_cheap', 'too_expensive'):.2f}")
print(f"indifference (cheap x expensive):         {crossing('cheap', 'expensive'):.2f}")
print(f"upper bound (cheap x too expensive):      {crossing('cheap', 'too_expensive'):.2f}")
```

將輸出視為要在內部進行測試的範圍，而不是答案：陳述的意願不同於
人們支付的費用，該方法忽略了數量。透過對新註冊的即時測試進行確認。

### 7. 在提出變更之前對變更進行建模

- 只要因以下原因而損失的客戶份額不變，價格上漲 `r` 就能維持收入水平
  它保留在`r / (1 + r)`下。再加上20%可以容忍16.7%。
- 降價 `d` 需要 `d / (1 - d)` 更多客戶才能達到收支平衡。負 20% 需要多 25%。
- 對於每位客戶的實際變動成本，對邊際貢獻也採取同樣的做法。每個計劃的模型和
  隊列（每月、每年、折扣、遺留），新增悲觀案例，並標記假設。

### 8. 規劃遷移

| 現有客戶的選項 | 適合 | 成本 |
|---|---|---|
| 無限期保留舊價格|基數小，忠誠度強，舊計劃便宜維持|永久遺留目錄；基礎上沒有收入增益 |
| 保留固定期限，然後移動 | 大多數情況 | 需要兩次通知和提醒 |
| 下次續約時移動 | 年度合約 | 緩慢；距離完成還有一年 |
| 通知所有人在某一天搬家 | 價格遠低於價值，或成本上升 | 流失風險最高；需要最好的解釋|

Stripe 中的機制：價格金額在建立後無法編輯。創造新價格，
將查找鍵移至該位置，以便網站和結帳系統將其選中，將舊的存檔存檔以進行新的銷售，
然後按照自己的步調更新每個訂閱：

```bash
curl https://api.stripe.com/v1/prices -u "$STRIPE_SECRET_KEY:" \
  -d product=prod_QmT4vLx81nBkWz -d unit_amount=3500 -d currency=usd \
  -d "recurring[interval]"=month -d lookup_key=growth_monthly -d transfer_lookup_key=true

curl https://api.stripe.com/v1/subscriptions/sub_1Pz8MdJr4Yt2WqLc \
  -u "$STRIPE_SECRET_KEY:" \
  -d "items[0][id]"=si_QpW3xN7uB5kTfa -d "items[0][price]"=price_1Q2kXeJr4Yt2WqLcH9dVmS0b \
  -d "items[0][quantity]"=4 -d proration_behavior=none
```

命名現有訂閱項目或將新價格加到舊價格旁邊；重複
數量或重設為 1。在相同的計費間隔且不按比例分配的情況下，首先是新金額
出現在下一張續約發票上。

注意：告訴每位客戶自己的新舊金額、日期、自新增以來的內容
最後一次更改以及他們的選項（按舊價格每年、較小的計劃、取消）。加州
請消費者訂閱提前 7 至 30 天收到費用變更通知，並可取消
說明。在Apple的App Store上，增加可能需要每個訂閱者的同意，並且
不同意的訂戶在期限結束時失效；現有訂閱者可以保留
他們的價格。合約條款和其他司法管轄區是使用者顧問的問題。

### 9. 提交備忘錄並進行衡量

備忘錄有以下部分： 證據診斷；公制；計畫表（買家、標題
限制、差異化因素、月費和年度價格）；研究總結；收入模式與
收支平衡；以群組劃分的遷移表；通知文字；風險；將測量什麼。

發布後，按價格版本和計劃進行比較：註冊到付費轉換、每個帳戶的收入、
更改後第一次續約時的計畫組合、折扣交易份額、流失和降級，
與計費相關的支援聯絡人。提前決定哪個結果會逆轉變更。

## 範例

### 範例 1：忽略帳戶規模的統一價格

請求：「Reedcount 是庫存軟體，每月固定價格 49 美元，擁有 1,900 名客戶。大型倉庫
費用與車庫相同。修好它。 」

使用情況匯出顯示每個帳戶的位置將客戶分開（1,210 個有一個，540 個有
2 到 5 個，150 個有 6 個或更多），位置越多的帳戶流失率就會降低一半，並且
訂單量季節性太強，買家無法預測。建議：

| 計劃 | 買家 | 價格 | 標題限制 | 差異化因素 |
|---|---|---|---|---|
| 單一 | 一間倉庫 | 每月 49 美元 | 1 個地點 | 核心庫存，條碼掃描 |
| 多個 | 擁有多個地點的商店 | 49 美元 + 每個額外地點 25 美元 | 5 個地點 | 地點之間轉移，每個地點的低庫存規則 |
| 網路 | 經銷商 | 149 美元 + 5 個以上每個地點 15 美元 | 無 | 採購訂單批准、API、審核日誌 |

模型：如果 2 到 5 人的組別平均有 3.5 個位置，而 6 人以上的組別平均有 7 個位置，那麼在清單中
如果不造成損失，每月收入將從 93,100 美元增加到約 146,000 美元
（1,210 × 49 美元 + 540 × 111.50 美元 + 150 × 179 美元）。該備忘錄並未承諾：現有帳戶可保留 49 美元六個月，帳單不超過
第一年就翻倍，悲觀的情況是假設 15% 的多地點帳戶離開。
新註冊者會立即獲得新計劃，這會在基礎移動之前測試指標。

### 範例 2：提高兩年內未變動的價格

請求：「Mossline 對最多 5,000 名訂閱者每月收費 29 美元。3,400 名客戶，每月流失
2.1%。自上次更改以來，我們已經發布了自動化和可交付性報告。多少錢可以
我們提高？ 」

代理調查活躍客戶並運行腳本：

```text
199 of 212 respondents usable (answers in ascending order)
lower bound (too cheap x expensive):      22.00
optimal (too cheap x too expensive):      29.00
indifference (cheap x expensive):         31.00
upper bound (cheap x too expensive):      39.00
```

建議：新客戶35美元，在該範圍內並低於其上限；每人收入
除非註冊轉換率下降超過 17.1% (6 / 35)，否則訪客將保留。現有客戶搬遷
提前 60 天通知後降至 33 美元；這對收入是中性的，除非超過 12.1% 的人因此而離開
(4 / 33)，假設損失 4%，每月收入將從 98,600 美元增加到 107,712 美元。任何人都可以
在日期之前預付一年費用 29 美元。備忘錄提前修正了逆轉規則：如果超過8%
的現有客戶在兩個計費週期內以價格為由取消預訂，基本價格將恢復至 29 美元。

## 指南

- 不要複製競爭對手的價目表或增加成本利潤。競爭對手向買家展示什麼
  比較並確定成本底線；價值和替代方案決定了剩下的事情。
- 不要添加計劃來解決折扣問題。修復包裝或折扣政策。
- 同時向相似的訪客顯示不同的價格具有法律和聲譽
  風險。跨時間、市場或計劃設計進行測試，或公開聲明正在測試定價。
- 切勿在未經通知的情況下更改現有客戶支付的金額，也切勿透過編輯金額來更改現有客戶的支付金額
  地方。舊價格將保留為存檔的 Price 對象，直到最後一個訂閱離開它們為止。
- 年度折扣交易保證金可換取現金和保留。將折扣表示為免費月份，並且
  在選擇其大小之前比較年度和每月保留率。
- 至少每年以及在價值變化的版​​本發布後重新審視定價，因此漲幅保持較小。
- 何時不使用此技能：問題在於升級螢幕（paywall-upgrade-cro）、佈局
  公共定價頁面（page-cro）的，或自訂工作的一次性報價。
