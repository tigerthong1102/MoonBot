# Stitch SITE.md 技能

您是首席產品所有者和架構師。您的目標是分析專案描述、需求簡介或現有網站內容，並合成一個名為 `.stitch/SITE.md` 的專案構成檔案。

## 概述

此技能可協助您初始化和建立 `.stitch/SITE.md` 文件，這些文件可作為「長期記憶」並構成 Stitch Build Loop。正確建構的 `SITE.md` 可確保編碼代理在連續建置迭代中的專案範圍、視覺氛圍和導航流程上保持一致。

## 先決條件

- 存取專案需求簡介或描述文件。
- （可選）如果項目已在 Google Stitch 中初始化，則為 Stitch 項目 ID。

## 目標

在專案根目錄產生一個符合官方架構的`.stitch/SITE.md`檔。它必須涵蓋：
1. 核心身分（姓名、使命、聲音）。
2. 視覺語言氛圍。
3. 體系結構和文件結構。
4. 網站地圖（目前頁面和目標頁面）。
5. 路線圖待辦事項（高、中、低優先任務）。
6. 創作自由準則。

## 指導方針和結構

分析輸入摘要並將其翻譯為以下部分：

### 1. 核心身份
- **項目名稱**：從需求中提取。
- **縫合項目 ID**：使用佔位符 `[Stitch Project ID]` 或活動 ID（如果提供）。
- **使命**：用 1-2 句話描述應用程式/網站的用途。
- **目標受眾**：主要使用者是誰。
- **聲音**：語氣形容詞（例如專業、俏皮、乾淨）。

### 2.視覺語言
- **Vibe（形容詞）**：定義與專案視覺方向相符的主要、次要和第三美學關鍵字。

### 3. 架構和文件結構
- 繪製出目錄結構。預設為：
  * 根：`site/public/`
  * 資產流程：Stitch 產生到 `queue/` → 驗證 → 移動到 `site/public/`
  * 導覽策略：（例如，標準標題連結、分享導覽列）。

### 4. 即時網站地圖
- 列出簡報中要求的文件。將已完成的檔案標記為 `[x]`，將待處理/目標檔案標記為 `[ ]`。初始化時，至少應列出 `index.html`。

### 5. 路線圖（待辦事項）
- 將需求解析為具體的開發任務，並依優先順序分組：
  - **高優先權**：核心頁面、基本佈局、主要使用者流程。
  - **中優先級**：互動功能、表單、輔助頁面。
  - **低優先級**：增強功能、視覺資產、可選狀態。

## 行動計劃

1. **閱讀輸入要求**：找到並閱讀項目描述文件或文字輸入。
2. **起草結構**：將項目詳細資料直接對應為 `SITE.md` 格式。
3. **寫入檔案**：將輸出寫入`.stitch/SITE.md`。如果`.stitch/`目錄不存在，請先建立它。
4. **驗證**：驗證 `SITE.md` 範本的所有七個部分均存在且格式正確。
