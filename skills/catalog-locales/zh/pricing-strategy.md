# 定价策略

## 概述

定价是三项决策、一项操作。决策：客户支付的单位（
价值指标）、每个计划包含的内容（包装）以及金额（级别）。操作方式：移动
新客户和现有客户都可以在不破坏账单或信任的情况下获得结果。大多数定价问题
坐在前两个决定中；大多数定价项目只涉及第三个。

这项技能始于企业已经拥有的证据（账单记录、每个帐户的使用情况、
销售说明），在证据薄弱的地方添加研究，并以带有迁移的定价备忘录结束
计划。没有付费客户的产品仍会走第 2 步中的捷径。

## 使用说明

### 1. 收集事实

读取 `.claude/product-marketing-context.md`（如果存在）。了解代码中如何定义计划
（搜索计划名称、限制和价格标识符）并导出当前目录：

```bash
curl -G https://api.stripe.com/v1/prices -u "$STRIPE_SECRET_KEY:" \
  -d active=true -d limit=100 -d "expand[]"=data.product
```

然后在可能的情况下获取每个帐户：计划、折扣后实际支付的金额、开始日期、
计费周期、席位、每个候选指标的使用情况、使用的功能以及帐户是否
搅动或扩大。询问用户哪些数据无法告诉用户：

1. 目标：每个客户获得更多收入、更多客户、更大的买家或覆盖使用成本。
2. 已经做出的承诺：“终身锁定价格”、合同条款、订单中的续约上限。
3. 交易如何完成：自助服务、销售协助或两者兼而有之，以及需要折扣的频率。
4. 买家指定的替代方案，包括不执行任何操作或使用电子表格。

### 2. 还没有客户：设定第一个价格

如果没有什么可诊断的，请跳过步骤 3 和 8，并保持结构最小化：一个指标、一个或
两种计划，按月和按年计费，试用而不是免费计划，直到知道付费原因为止。

- 把价格括起来。底价：每个客户的可变成本加上付款费用。天花板：结果如何
  对买方来说是值得的（节省的时间乘以每小时的成本、获得的收入、更换的工具）。
  参考：他们今天在替代方案上花费了多少钱，包括手工完成这项工作。
- 采访 10 至 15 名目标买家。询问他们现在使用什么以及费用是多少，展示产品，
  然后说出价格并观察反应。 “你愿意付什么钱？”产生低且不可靠的数字。
- 请求承诺（预订、付费飞行员、存档卡）；意见不等于购买。
- 从买家不议价就接受的上半部分中选择。价格太低
  不能与需求疲软区分开来，而且后期折价比加价更容易。
- 以标价的日期折扣（而不是更低的标价）奖励早期客户。
- 前 20 至 30 名付费客户或 90 天后进行审核；记录反对意见并立即表示同意。

### 3.找到薄弱环节

| 证据 | 可能的问题 | 转到 |
|---|---|---|
| 5 人账户和 500 人账户支付相同的费用 | 指标不遵循值 | 步骤 4 |
| 账单波动和客户要求上限，或者为了省钱而限制使用量 | 指标是不可预测的或惩罚采用 | 第 4 步 |
| 80% 的客户采用一种计划，或者销售人员不断分拆功能以关闭 | 计划与买家群体不匹配 | 第 5 步 |
| 几乎没有价格异议，折扣很少，成交率异常高 | 级别太低 | 第 6 步 |
| 大多数交易都需要折扣；流失原因提到价格 | 对于显示的价值来说级别过高，或者买家错误 | 步骤 5 和 6 |
| 免费帐户保持活跃数月且从不付费 | 免费计划给出了付费原因 | 第 5 步 |

### 4. 选择价值指标

根据使用数据而不是意见对每个候选人进行评分：

| 测试| 如何检查|
|---|---|
| 随着客户获得的价值而增长 | 拥有更多价值的帐户保留并扩展更多 |
| 买家可以预测账单 | 他们可以在发票前注明下个月的数字 |
| 可计数、可审核 | 产品已记录并可展示给客户 |
| 不会阻止使产品粘性的行为 | 协作功能的每席位定价会抑制邀请 |
| 将客户分散开来 | 如果 90% 的帐户属于最低范围，则不会将任何人分开 |
| 当成本重要时遵循成本 | 计算、消息、AI 调用 |

形式：固定费用、每个座位、计量使用、带使用范围的计划、平台费加使用量、每个
结果。当两个指标得分良好时，就对其中一个指标进行控制，并用另一个指标来制定计划。对于分层
使用量，在分级等级（每个单位按其所属范围定价）和数量等级之间进行选择
（所有单位按区间定价）；毕业避免了账单下降到阈值。

### 5. 打包计划

1. 根据需要命名买家群体，其中两到四个。公司规模只是一个指标，而不是一个需要。
2. 根据每组的采用情况，加上最佳/最差排名，将每个功能分类到四个箱之一
   当未发布功能的采用数据丢失时进行调查（MaxDiff）：
   - **每个计划：**需要达到核心价值。门控它会减少激活。
   - **计划差异化因素：** 一组晋升的原因。每个计划一到三个。
   - **附加功能：**受到跨群体的少数人的高度重视。
   - **针对大买家的控制：**安全审查项目、审核日志、正常运行时间条款、发票。
3. 给每个计划一个价值指标的标题限制，因此下一个计划就是以下问题的答案：
   增长而不是寻找功能。
4. 每个计划都需要指定买家。一个不适合任何人选择的计划是混乱的。
5. 免费计划或试用：免费计划适合帐户服务成本较低且免费用户带来的情况
   其他或内容；当价值在几天内显现并且服务成本显着时，限时试用适合
   是真实的。无论哪种方式，付费原因都必须排除在免费津贴之外。

### 6. 设置级别

证据，最有力的第一：真实买家接受或拒绝的价格（赢利说明、折扣
历史记录，对新注册用户的实时测试），然后是调查，然后是竞争对手的价目表，其中显示了
买家的参考点，与你的价值无关。

调查方法：

- **价格敏感度计（Van Westendorp）：** 每个受访者有四个开放性问题：价格为
  该产品太便宜而无法信任，讨价还价，变得昂贵，并且太贵而无法信任
  考虑。产量在可接受的范围内。
- **Gabor-Granger：** 价格阶梯的购买意向；需求乘以价格给出收入曲线。
- **联合：**捆绑之间的选择；包装和价格相互作用时的正确工具，以及
  三者中唯一需要专业软件的之一。

询问与目标买家匹配并了解该产品的人，每个计划和一个计费周期
问题。将每组少于 100 个可用答案视为定向答案。

```python
"""Usage: python3 psm.py survey.csv
Columns, one row per respondent, same currency and billing period: too_cheap, cheap, expensive, too_expensive"""
import csv, sys

rows = [{k: float(v) for k, v in r.items()} for r in csv.DictReader(open(sys.argv[1]))]
valid = [r for r in rows if r["too_cheap"] <= r["cheap"] <= r["expensive"] <= r["too_expensive"]]
n = len(valid)
grid = sorted({v for r in valid for v in r.values()})

def at_least(col, p): return sum(r[col] >= p for r in valid) / n   # falls as the price rises
def at_most(col, p): return sum(r[col] <= p for r in valid) / n    # rises with the price

def crossing(falling, rising):
    prev = None
    for p in grid:
        gap = at_least(falling, p) - at_most(rising, p)
        if gap <= 0:
            if prev is None or gap == 0: return p
            p0, g0 = prev
            return p0 + (p - p0) * g0 / (g0 - gap)
        prev = (p, gap)

print(f"{n} of {len(rows)} respondents usable (answers in ascending order)")
print(f"lower bound (too cheap x expensive):      {crossing('too_cheap', 'expensive'):.2f}")
print(f"optimal (too cheap x too expensive):      {crossing('too_cheap', 'too_expensive'):.2f}")
print(f"indifference (cheap x expensive):         {crossing('cheap', 'expensive'):.2f}")
print(f"upper bound (cheap x too expensive):      {crossing('cheap', 'too_expensive'):.2f}")
```

将输出视为要在内部进行测试的范围，而不是答案：陈述的意愿不同于
人们支付的费用，该方法忽略了数量。通过对新注册的实时测试进行确认。

### 7. 在提出变更之前对变更进行建模

- 只要由于以下原因而损失的客户份额不变，价格上涨 `r` 就能保持收入水平
  它保留在`r / (1 + r)`下。再加上20%可以容忍16.7%。
- 降价 `d` 需要 `d / (1 - d)` 更多客户才能实现收支平衡。负 20% 需要多 25%。
- 对于每个客户的实际可变成本，对边际贡献也采取同样的做法。每个计划的模型和
  队列（每月、每年、折扣、遗留），添加悲观案例，并标记假设。

### 8. 规划迁移

| 现有客户的选项 | 适合 | 成本 |
|---|---|---|
| 无限期保留旧价格|基数小，忠诚度强，旧计划便宜维持|永久遗留目录；基础上没有收入增益 |
| 保留固定期限，然后移动 | 大多数情况 | 需要两次通知和提醒 |
| 下次续签时移动 | 年度合同 | 缓慢；距离完成还有一年 |
| 通知所有人在某一天搬家 | 价格远低于价值，或者成本上升 | 流失风险最高；需要最好的解释|

Stripe 中的机制：价格金额在创建后无法编辑。创建新价格，
将查找键移至该位置，以便网站和结帐系统将其选中，将旧的存档存档以进行新的销售，
然后按照自己的节奏更新每个订阅：

```bash
curl https://api.stripe.com/v1/prices -u "$STRIPE_SECRET_KEY:" \
  -d product=prod_QmT4vLx81nBkWz -d unit_amount=3500 -d currency=usd \
  -d "recurring[interval]"=month -d lookup_key=growth_monthly -d transfer_lookup_key=true

curl https://api.stripe.com/v1/subscriptions/sub_1Pz8MdJr4Yt2WqLc \
  -u "$STRIPE_SECRET_KEY:" \
  -d "items[0][id]"=si_QpW3xN7uB5kTfa -d "items[0][price]"=price_1Q2kXeJr4Yt2WqLcH9dVmS0b \
  -d "items[0][quantity]"=4 -d proration_behavior=none
```

命名现有订阅项目或将新价格添加到旧价格旁边；重复
数量或重置为 1。在相同的计费间隔且不按比例分配的情况下，首先是新金额
出现在下一张续订发票上。

注意：告诉每个客户自己的新旧金额、日期、自添加以来的内容
最后一次更改以及他们的选项（按旧价格每年、较小的计划、取消）。加利福尼亚州
要求消费者订阅提前 7 至 30 天收到费用变更通知，并可取消
说明。在Apple的App Store上，增加可能需要每个订阅者的同意，并且
不同意的订户在期限结束时失效；现有订阅者可以保留
他们的价格。合同条款和其他司法管辖区是用户顾问的问题。

### 9. 提交备忘录并进行衡量

备忘录有以下部分： 证据诊断；公制；计划表（买家、标题
限制、差异化因素、月度和年度价格）；研究总结；收入模式与
收支平衡；按群组划分的迁移表；通知文字；风险；将测量什么。

发布后，按价格版本和计划进行比较：注册到付费转化、每个帐户的收入、
更改后第一次续订时的计划组合、折扣交易份额、流失和降级，
与计费相关的支持联系人。提前决定哪个结果会逆转更改。

## 示例

### 示例 1：忽略账户规模的统一价格

请求：“Reedcount 是库存软件，每月固定价格 49 美元，拥有 1,900 名客户。大型仓库
费用与车库相同。修好它。”

使用情况导出显示每个帐户的位置将客户分开（1,210 个有一个，540 个有
2 到 5 个，150 个有 6 个或更多），位置越多的账户流失率就会降低一半，并且
订单量季节性太强，买家无法预测。建议：

| 计划 | 买家 | 价格 | 标题限制 | 差异化因素 |
|---|---|---|---|---|
| 单个 | 一间库房 | 每月 49 美元 | 1 个地点 | 核心库存，条形码扫描 |
| 多个 | 拥有多个地点的商店 | 49 美元 + 每个额外地点 25 美元 | 5 个地点 | 地点之间转移，每个地点的低库存规则 |
| 网络 | 分销商 | 149 美元 + 5 个以上每个地点 15 美元 | 无 | 采购订单批准、API、审核日志 |

模型：如果 2 到 5 人的小组平均有 3.5 个位置，而 6 人以上的小组平均有 7 个位置，那么在列表中
如果不造成损失，每月收入将从 93,100 美元增加到约 146,000 美元
（1,210 × 49 美元 + 540 × 111.50 美元 + 150 × 179 美元）。该备忘录并未承诺：现有账户可保留 49 美元六个月，账单不超过
第一年就翻倍，悲观的情况是假设 15% 的多地点账户离开。
新注册者会立即获得新计划，这会在基础移动之前测试指标。

### 示例 2：提高两年内未变动的价格

请求：“Mossline 对最多 5,000 名订阅者每月收费 29 美元。3,400 名客户，每月流失
2.1%。自上次更改以来，我们已经发布了自动化和可交付性报告。多少钱可以
我们提高？”

代理调查活跃客户并运行脚本：

```text
199 of 212 respondents usable (answers in ascending order)
lower bound (too cheap x expensive):      22.00
optimal (too cheap x too expensive):      29.00
indifference (cheap x expensive):         31.00
upper bound (cheap x too expensive):      39.00
```

建议：新客户35美元，在该范围内并低于其上限；每人收入
除非注册转化率下降超过 17.1% (6 / 35)，否则访客将保留。现有客户搬迁
提前 60 天通知后降至 33 美元；这对收入是中性的，除非超过 12.1% 的人因此而离开
(4 / 33)，假设损失 4%，每月收入将从 98,600 美元增至 107,712 美元。任何人都可以
在日期之前预付一年费用 29 美元。备忘录提前修正了逆转规则：如果超过8%
的现有客户在两个计费周期内以价格为由取消预订，基本价格将恢复至 29 美元。

## 指南

- 不要复制竞争对手的价目表或增加成本利润。竞争对手向买家展示什么
  比较并确定成本底线；价值和替代方案决定了剩下的事情。
- 不要添加计划来解决折扣问题。修复包装或折扣政策。
- 同时向相似的访客显示不同的价格具有法律和声誉
  风险。跨时间、市场或计划设计进行测试，或公开声明正在测试定价。
- 切勿在未经通知的情况下更改现有客户支付的金额，也切勿通过编辑金额来更改现有客户的支付金额
  地方。旧价格将保留为存档的 Price 对象，直到最后一个订阅离开它们为止。
- 年度折扣交易保证金可换取现金和保留。将折扣表示为免费月份，并且
  在选择其大小之前比较年度和每月保留率。
- 至少每年以及在价值发生变化的版本发布后重新审视定价，因此涨幅保持较小。
- 何时不使用此技能：问题在于升级屏幕（paywall-upgrade-cro）、布局
  公共定价页面（page-cro）的，或定制工作的一次性报价。
